# 🧠 Guia Prático: Implementando o Projeto AWS Free Tier (Abstergo Industries)

> **Contexto:**  
> Projeto pessoal e fictício criado para estudar e testar conhecimentos de AWS.  
> Todo o ambiente foi configurado usando o **Free Tier da AWS (2025)**, com foco em praticar a criação de uma **infraestrutura web escalável e monitorada**.

---

## 🛠️ Estrutura geral do projeto

1. Preparar conta e IAM (user + MFA)  
2. Criar bucket S3 (assets) com versionamento + bloquear acesso público  
3. Lançar uma EC2 (Amazon Linux) com user-data para instalar webserver + CloudWatch Agent  
4. Criar Target Group e Application Load Balancer (ALB)  
5. Criar Launch Template/Configuration + Auto Scaling Group (ASG) ligado ao ALB  
6. Configurar CloudWatch: dashboards & alarmes; instalar CloudWatch Agent para métricas de memória/disk  
7. Testar com carga leve; monitorar billing/Free Tier  
8. Limpar recursos quando terminar (para evitar cobranças 😅)

---

## 🧩 1) Criar um grupo IAM e um usuário de deploy (GUI)

**Por que:** nunca use a root account para tarefas do dia a dia. Crie um usuário com permissões controladas e habilite MFA.

### Passo a passo

1. No Console AWS, pesquise por **“IAM”** e acesse o serviço.  
2. No menu lateral, clique em **User groups** → **Create group**.  
3. Nome do grupo: adm-abstergo
4. Em **Attach permissions policies**, procure e adicione:
- `AmazonEC2FullAccess`
- `AmazonS3FullAccess`
- `CloudWatchFullAccess`
- `ElasticLoadBalancingFullAccess`
- `AutoScalingFullAccess`
5. Clique em **Create group**.

6. Agora, ainda no IAM, vá para **Users** → **Create user**:
- Nome do usuário: 
- Selecione “Provide user access to the AWS Management Console”.
- Marque **Autogenerated password** (ou defina um).
- Marque “User must create a new password at next sign-in”.

7. Clique em **Next**, e adicione o usuário ao grupo **adm-abstergo**.  
8. Clique em **Create user**.

9. Após criado, abra o usuário → aba **Security credentials** → **Assign MFA** → configure MFA virtual (ex: Authy, Google Authenticator).  
10. Anote o **Login URL personalizado** (IAM sign-in URL) para usar depois.

## 🪣 2) Criar um bucket S3 para assets (imagens, backups, etc.)

**Por que:** o bucket servirá para armazenar imagens, arquivos estáticos e backups de forma durável e escalável.

### Passo a passo (Console)

1. Pesquise **S3** no Console AWS → **Create bucket**.  
2. Nomeie o bucket:
3. Região: selecione a mesma região que usará para EC2 (ex: `us-east-1` ou `sa-east-1`).  
4. **Desmarque** a opção “Block *all* public access” apenas se precisar de acesso público.  
- Neste projeto, mantenha **bloqueado** e use acesso via IAM Role.  
5. Em **Bucket Versioning**, marque **Enable**.  
6. Clique em **Create bucket**.
7. Habilite o **versionamento** do bucket em propriedades
